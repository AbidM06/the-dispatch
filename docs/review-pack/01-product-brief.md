# The Dispatch — product brief

Everything below is drawn from the codebase, not from intent. Where a feature is
partial or degraded, it says so.

## One line

A personal market intelligence dashboard built by an economics student: live
macro rates, AI-generated sell-side research, a watchlist, a trade-idea engine
with Shariah screening, a correlation/backtest lab, and an S&T interview prep
module — served as an Express API with a single-file React front end.

## Who built it and why

One person, self-taught, using it to learn markets and to prepare for sales &
trading / asset management interviews. It is a personal tool, not a product with
users. That matters for the review: the question is not "would this scale to
10,000 customers", it is "is this a good instrument for one person to understand
markets with, and does it demonstrate competence".

## Shape

- Node/Express API on port 3001.
- `client/index.html` — a single 6,400-line React 18 file using `createElement`
  directly. No JSX, no bundler, no build step.
- All API keys are server-side. The browser only ever calls `/api/...`.
- In-memory TTL cache with a four-stage degradation path: warm cache → live
  fetch → stale cache (flagged `stale: true`) → seed fallback.

## The ten tabs

| Tab | What it does |
|---|---|
| **Snapshot** | Live FRED rates (10Y nominal, 10Y real, breakeven, HY OAS, 2s10s curve), USD/GBP, watchlist prices, RSI, charts |
| **Risk** | AI-scored risk monitor across 7 channels, refreshable against live news |
| **Analytics** | Cross-asset correlation engine, MA-crossover backtester, momentum scanner, model builder with in-sample/out-of-sample split, AI narrative |
| **Desk** | Trade idea tracker, risk/reward checks, AI idea generation, position sizing |
| **Sales** | S&T macro view — morning note, scenario grid, cross-asset matrix, central bank reaction functions, client impact map |
| **News** | Finnhub headlines, economic + earnings calendar, company news and sentiment, AI morning bulletin with a 1-minute pitch script |
| **Research** | Six AI sell-side report types (below) |
| **Glossary** | 80+ S&T / AM terms with definitions, Islamic-finance notes, and interview angles |
| **Engine** | Automated idea engine with playbooks, Shariah universe scanner (33 tickers), historical backtester, execution audit log |
| **Interview** | Flashcards for S&T / AM prep — behavioural, markets, investment, product |

## The six research report types

Generated by Claude with the `web_search` server tool, one schema per type:

- **MACRO** — global economics comment: transmission, central bank policy, cross-asset
- **COMMODITIES** — supply/demand, price targets
- **EQUITY** — US equity views: EPS, AI capex uplift, sector rotation, consensus vs house view
- **FX** — G10 pair views, central bank reaction functions
- **RATES** — rates and carry, positioning, catalysts, level targets
- **THEMATIC** — structural themes, predictions, key debates, stock focus list

## Data sources and their real limits

| Source | Used for | Constraint that shapes the design |
|---|---|---|
| FRED | 11 series: rates, HY OAS, curve, Brent, WTI, VIX, EUR/USD | Free, effectively unlimited. Daily granularity only |
| Alpha Vantage | AMD quote + USD/GBP only | 25 calls/day — deliberately limited to 2 calls per refresh |
| Polygon.io | 6 watchlist peers (NVDA, MSFT, TSLA, MU, AMAT, LRCX) | Free tier: daily aggregates only, ~15-min delay. Snapshot endpoint is paid |
| Finnhub | News, earnings + economic calendar, sentiment | 60 req/min |
| EIA | Commodity price history | Weekly, ~1 week lag |
| ExchangeRate-API | USD/GBP fallback when Alpha Vantage FX fails | Keyless free endpoint, no SLA, no observation timestamp |
| Yahoo Finance | Unofficial fallback quote route in `polygon.js` | Undocumented endpoint, no terms of use for this purpose, can change without notice |
| Anthropic | All AI surfaces | Metered — daily/monthly spend caps exist in code |
| OpenAI | Fallback only, when Claude fails | Has no web search, so its output is flagged `grounded: false` |

**There is no intraday price feed, no order book, no options data, no CME
FedWatch, no Bloomberg.** Every design decision downstream follows from that.

*Correction to the version of this brief circulated for external review:* that
version listed seven sources and omitted the last two rows above. Reviewers
therefore assessed the data stack without knowing that two of the price paths
fall back to a keyless endpoint and an undocumented one. The omission was in the
brief, not the code.

## Accuracy architecture — the part most worth reviewing

The project was recently rebuilt around a single complaint: reports asserted
figures that were wrong, and nothing in the output let a reader tell a measured
number from an invented one. What exists now:

- **One fact source for every report.** `server/providers/macroContext.js`
  fetches 11 FRED series in parallel and hands them to every report type. Each
  returns as a Fact carrying its own `source`, `seriesId` and `asOf` — the
  observation date, not the fetch time. Failures are named in `missing` so
  "not fetched" stays distinguishable from "fetched as zero".
- **The prompt forbids searching for figures already supplied**, which is both
  an accuracy and a cost measure.
- **The Fed policy path is an explicitly labelled proxy.** There is no free
  documented API for CME FedWatch, so the code does not pretend to have one: it
  computes 2Y UST minus effective fed funds with a ±25bp neutral band and reports
  a *direction*. Every field states it is not a market-implied probability.
- **Citations resolve to URLs.** What `web_search` actually returned is surfaced
  as `citedSources` and `allSources` and rendered as footnotes.
- **The model must declare its own estimates.** `estimates[]` is where it lists
  figures that are its forecasts rather than measurements; `unverified[]` is what
  it could not confirm. Both render as separate tables.
- **No fabricated fallbacks — now true of the Sales tab too.** Six hardcoded
  "deterministic" reports used to be served on research failure; they read
  exactly like live research while asserting things that never happened,
  including a Strait of Hormuz closure with a 17mb/d supply shock. They were
  deleted. The external review then found the same pattern still live in
  `server/routes/macro.js`, which served an invented Fed level, invented
  60/20/20 scenario probabilities, an invented trade idea with entry/stop/target
  and dated CPI/FOMC/NFP catalysts. Those are now deleted as well, and both
  Sales endpoints return HTTP 503 with the same unavailable contract. A test
  asserts neither set comes back.
- **The Sales tab's "live FRED data" was not live.** `rateVal()` looked for an
  `observations` array that `getAllRates()` never returns, so it returned its
  hardcoded defaults on every call — and those defaults were passed into the AI
  prompt labelled as latest FRED data. Fixed: it reads the Fact's `.value`, and
  missing data is null rather than a plausible constant.

## Safety posture

- All execution is off by default. Paper trading requires three separate env
  flags plus Alpaca credentials, and Alpaca's base URL must contain "paper".
- Circuit breakers: max 3 trades/day, £250 notional/day, 5 open positions, 20%
  single-ticker exposure, and a freshness gate that skips execution if data is
  more than 20 minutes old. The review established that only the first of these
  actually bound: the notional cap was tested against a £100 placeholder before
  sizing ran, the open-position and exposure caps were never passed the inputs
  they need, a blocked sizing decision was downgraded to a 1-share order, and
  the freshness gate measured cache-write time rather than the observation date.
  All four are fixed; the caps now see the real order.
- Shariah enforcement: short positions are rejected at both the API and the
  engine, on the *gharar* prohibition.
- Write routes are guarded by an admin key when one is configured.

## Known limitations — stated, not hidden

1. **No intraday data.** Positions and risk are computed off daily closes and
   15-minute-delayed aggregates.
2. ~~**The spend caps do not work.**~~ Fixed. `budget.js` used
   `parseInt(process.env.X, 10) ?? N`; `parseInt(undefined, 10)` is `NaN`, which
   is neither null nor undefined, so `??` never fired and both caps were `NaN` —
   every comparison against them false. It now parses explicitly, rejects
   non-numeric input, and honours a deliberate `0`.
3. **`web_search` has no `max_uses` cap.** Per-report search cost is unbounded.
   Still unfixed, and known.
4. **One test fails on a clean checkout.** A date-dependent event-horizon
   assertion in `tests/phase1.test.js`. 291 of 292 pass.
4b. **`narrativeEngine.js` still hardcodes market claims.** Its invented
   *portfolio* figures are gone, but the LOW_COST_MODE prose still asserts
   specific things about the world — a named GPU order, a quarterly revenue
   guide — with no source and no as-of date. Same failure class as the deleted
   fallbacks; not yet fixed.
4c. **One instrument's asset class is contested inside the repo.** HBKS is
   catalogued as a UK equity ETF in the Shariah filter and traded as a duration
   instrument by a playbook. The playbook is held rather than guessed at.
5. **The front end is one 6,400-line file** with no component tests.
6. **No CI.** There is no `.github/workflows`; tests run locally only.
7. **The backtester runs on seeded historical data**, not a live price history —
   it is deterministic by design, which also means it is not a real backtest of
   real fills.
8. **Single user, no auth beyond an optional shared admin key**, no
   multi-tenancy, no persistence layer beyond JSON and JSONL files on disk.
